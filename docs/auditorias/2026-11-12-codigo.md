# Audit: Colpa Belgica Conecta (code)

What this repo does: A municipal app. Residents read published notices (health, school, events) in an Expo/React Native app; a few officials write, review and publish them through an Express API (Vercel serverless, Postgres on Neon, images on Cloudinary).
Load assumed: hundreds to low thousands of readers on weak mobile signal, ~20 writers, several API instances with cold starts.
Read fully: all of apps/api/src (except generated), prisma schema/migrations/seed, packages/shared/src, apps/mobile/lib, hooks, TarjetaPublica, sesion, layouts, scripts. Skimmed: most mobile components, FormPublicacion (first 120 lines), tests (names only).

## Must fix

1. **Residents download full-size photos** (`apps/mobile/features/publico/TarjetaPublica.tsx:69`, `apps/api/src/services/imagen.service.ts:68`)
   - What this is: The home screen shows a 140px-high card with the notice image. The API builds the image URL as `.../image/upload/<public_id>.<fmt>`, the original upload.
   - Problem: A phone photo is 3-8 MB. The home screen can load up to 10 featured cards, and the detail screen loads all 4 images, each at full size. On weak signal this is slow and eats the resident's data plan.
   - Fix: Insert a Cloudinary transformation in the URL the server builds: `.../image/upload/f_auto,q_auto,w_800/<public_id>.<fmt>`. Add a one-line SQL update for rows already stored.
   - If we skip it: The main screen is slow or blank on rural networks. This is the first complaint you will get.

2. **Multi-day events disappear after the first day** (`apps/mobile/features/publicaciones/FormPublicacion.tsx`, `apps/mobile/features/publicaciones/ficha.ts:40-48`, `apps/api/src/services/publico.service.ts:41-43`)
   - What this is: "Current" notices are those whose end date (`fechaFin`) or, if empty, start date is today or later.
   - Problem: No screen lets an official set `fechaFin` (the form and the `EDITABLES` list have no such field; grep shows it is only displayed). So every notice ends on its start day. A fair that runs Friday to Sunday vanishes on Saturday.
   - Fix: Add an optional `fechaFin` field to the form and to `EDITABLES`/`parche`. The schema and API already accept it. If it is out of scope for now, say so in the handoff.
   - If we skip it: Residents miss ongoing events; officials cannot fix it.

3. **Mobile requests never time out** (`apps/mobile/lib/api.ts:55`)
   - What this is: One `fetch` wrapper for the whole app.
   - Problem: `fetch` has no timeout in React Native. On a half-dead connection (common in rural areas) it hangs, the spinner never ends, and the "no connection" message never shows.
   - Fix: `signal: AbortSignal.timeout(15000)` in the `fetch` call; the existing catch already turns it into the offline error.
   - If we skip it: Users see an endless spinner instead of a retry button.

## Should fix

4. **Every app open hits the database** (`apps/api/src/controllers/publico.controller.ts:7-8`, `apps/api/src/db.ts:8`)
   - What this is: Public list/detail send `Cache-Control: no-cache` plus an ETag. A 304 saves bandwidth but the server still runs the query to compute the ETag.
   - Problem: Each resident open = 2 DB queries. If Neon has scaled to zero, the first request pays the wake-up time and may hit the 5 s `connectionTimeoutMillis`. Content changes a few times a day.
   - Fix: Use `Cache-Control: public, s-maxage=60, stale-while-revalidate=300` on the three public GETs so Vercel's CDN absorbs repeats. Keep the ETag. Accept up to ~1 min delay after publishing (or lower to 30 s).
   - If we skip it: Fine at 100 users; at a few thousand, cold starts and Neon compute hours grow for no reason.

5. **Login lock has three weak spots** (`apps/api/src/services/auth.service.ts:26-43`)
   - What this is: Each login attempt first adds 1 to `intentos_fallidos`; at 5 the account is locked 15 min.
   - Problem (a): The counter never decays. Only a successful login resets it, so one typo a month locks a real user on the 5th month. (b) The lock is written in a second query after the check. If that query fails (Neon hiccup, function timeout), the counter stays at 5 with no `bloqueado_hasta`: the `WHERE intentos_fallidos < 5` then rejects even the right password forever, and no admin action clears it (only reactivation resets it). If that is the only admin, nobody can recover from the app. (c) Anyone who knows an account name (the admin's) can lock it every 15 min with 5 requests.
   - Fix: Set `bloqueado_hasta` inside the same UPDATE with a CASE when the new count reaches the maximum, and let the "reactivate"/edit path reset the counter. For (a) reset the counter when the last failure is older than the window (needs a `ultimo_intento` column or use `bloqueado_hasta`). (c) is a design trade-off; mention it to the CTO.
   - If we skip it: A rare but unrecoverable admin lockout, plus a cheap way to annoy officials.

6. **Account administration is not audited** (`apps/api/src/services/cuentas.service.ts:31-98`)
   - What this is: An admin can create accounts, change roles, deactivate users.
   - Problem: Only publication actions and logins are written to `registro_auditoria`. A role change to APROBADOR (who can publish) leaves no trace of who did it or when.
   - Fix: Call the same insert (entity `funcionario`, actions CREAR_CUENTA / CAMBIAR_ROL / DESACTIVAR) inside the existing transaction in `modificar` and around `crearCuenta`. `registrar` in auditoria.service.ts currently hard-codes entity `publicacion`; add an `entidad` parameter.
   - If we skip it: In a dispute ("who made X an approver?") there is no evidence.

7. **Nothing readable offline** (`apps/mobile/app/_layout.tsx:10`)
   - What this is: React Query cache lives in memory only.
   - Problem: A resident who opens the app with no signal sees the empty/error state even if they read the same notices an hour ago. There is an offline banner, but no data behind it. Unverified how important this is to the thesis scope.
   - Fix: Add `@tanstack/query-async-storage-persister` with AsyncStorage for the `publico` queries only (about 10 lines in `_layout.tsx`).
   - If we skip it: The "weak signal" use case works only while connected.

## Nice to have

8. **Four unused tables** (`apps/api/prisma/schema.prisma`: `Establecimiento`, `Dispositivo`, `Recordatorio`, `Notificacion` + their enums and relations on `Funcionario`)
   - What this is: Models for future modules (map of facilities, push notifications).
   - Problem: grep finds no use in src, tests or mobile. They add tables, ~60 schema lines and relations to maintain.
   - Fix: Delete them until the module is built, in a new migration. Skip if the thesis document requires them in the schema.
   - If we skip it: Only extra clutter.

9. **Image registration trusts the id, not the upload** (`apps/api/src/services/imagen.service.ts:62-86`)
   - What this is: After uploading to Cloudinary, the app tells the API the public id.
   - Problem: The API checks only the folder prefix and UUID shape, not that the file exists or was issued by `firmaSubida`. A staff member can register a never-uploaded id and publish a broken image link. Staff-only, so low risk.
   - Fix: Accept the risk, or do one HEAD request to the built URL before saving.
   - If we skip it: A broken image icon on a notice at worst.

10. **`/health` is open and always queries the DB** (`apps/api/src/routes/index.ts:33`)
    - What this is: Liveness check.
    - Problem: A script hammering it keeps Neon awake (compute cost) and uses connections; it is outside any rate limit.
    - Fix: Put it under `limitePublico` or drop the `SELECT 1` for the public path.
    - If we skip it: Small cost leak.

11. **Connection pool per instance** (`apps/api/src/db.ts:8`)
    - What this is: `pg` pool with default max 10 per serverless instance.
    - Problem: Many instances x 10 can exceed Neon's pooler limits during a spike. `rol-app.sql` documents the pooler URL, which mitigates it; not verified that production uses it.
    - Fix: `max: 3` in the `PrismaPg` options.
    - If we skip it: "too many connections" only under bursts.

12. **Repeated comment block** (`apps/api/src/routes/index.ts:35-51`)
    - What this is: Two near-identical `shortcut:` paragraphs about the in-memory limiter.
    - Fix: Keep one above both limiters, delete about 8 lines.

Left out (smaller): none counted beyond the above; the in-memory rate limit, Cloudinary orphans and the other known-debt items were not re-reported.

Verdict: Fix 1, 2 and 3 first (all about what residents experience on weak signal); then 5 and 6 before real officials get accounts.
Lean: -75 lines, -0 dependencies possible (items 8 and 12).
Not checked: ran nothing (read-only); the Jest suite results; most files in `apps/mobile/components` and the remaining 230 lines of `FormPublicacion.tsx`; `ImagenesFicha.tsx`; whether production uses the Neon pooler URL; whether the thesis document needs the unused tables; test coverage of the La Paz midnight boundary in `hoy()` (not found by name, not searched deeply). API test files were only listed, not read.
