## 1. No existe camino a un APK instalable — ALTO

**Evidencia**

**Arreglo concreto**

1. El CTO crea la cuenta Expo y luego `eas init`. Eso agrega el projectId y obliga a definir `android.package` (p. ej. `bo.gob.colpabelgica.conecta`; elegirlo ya, porque cambiarlo después invalida los tokens de push).
2. Crear `apps/mobile/eas.json` con un perfil `preview`: `"distribution": "internal"`, `"android": { "buildType": "apk" }`, `"env": { "EXPO_PUBLIC_API_URL": "https://colpa-belgica-conecta-api.vercel.app" }` (la URL no es secreta) y `"node": "24.x"`.
3. Lanzar el primer build **esta semana**, aunque sea sin push, para descubrir pronto los problemas de monorepo pnpm 11 en EAS.
4. Respaldo si la cola de EAS o la cuota fallan: `eas build --local` o `npx expo run:android --variant release`. Ambos necesitan Android SDK y JDK en la máquina, cosa no verificada.

**Esfuerzo:** 0,5–1 día más la espera de colas.
**No verificado:** soporte de pnpm 11.3.0 y Node 24 en las imágenes de EAS Build. La doc de monorepos (https://docs.expo.dev/build-reference/build-with-monorepos/) solo dice "Run all EAS CLI commands from the root of the app directory". Expo soporta las instalaciones aisladas de pnpm desde SDK 54 (https://docs.expo.dev/guides/monorepos/); si algo falla, `nodeLinker: hoisted` en `pnpm-workspace.yaml`.

## 2. Expo Go sirve para probar hoy, no para la demo — ALTO

**Hechos verificados**

- Expo Go con **SDK 58 está disponible para Android**: https://expo.dev/go muestra "SDK 58 (latest)" con instalación para Android.
- Expo Go de la App Store de Apple "stops at SDK 54" (https://docs.expo.dev/troubleshooting/expo-go-version-mismatch/). Para iOS no sirve, pero la demo es solo Android.
- Ninguna dependencia bloquea Expo Go: todas las nativas son módulos del SDK (`expo-image-picker`, `expo-secure-store`, `expo-network`, `expo-font`, etc.) y `react-native-paper` es JS puro.
- **Push remoto en Expo Go Android: no disponible desde SDK 53.** Cita: "Push notifications (remote notifications) functionality provided by `expo-notifications` is unavailable in Expo Go on Android from SDK 53. A development build is required" (https://docs.expo.dev/versions/latest/sdk/notifications/).

**El riesgo:** con Expo Go, el JS lo sirve Metro desde la laptop. La demo frente al tutor dependería de la laptop, de la red del aula (aislamiento de clientes en Wi-Fi universitario) o de `--tunnel`.

**Arreglo:** usar Expo Go solo para la prueba del núcleo de hoy (`EXPO_PUBLIC_API_URL=https://colpa-belgica-conecta-api.vercel.app pnpm --filter mobile start`, con `--tunnel` si el teléfono y la laptop no se ven). Para la demo, usar el APK `preview` del #1, que lleva el JS embebido y no necesita laptop.

**Recomendación:** sumar `expo-updates` al APK para iterar el JS con `eas update --channel preview` sin gastar builds (Free: 1.000 MAU). Cada cambio nativo (agregar `expo-notifications`, `expo-sqlite`) obliga a un build nuevo, así que **conviene agregar `expo-notifications` y `expo-sqlite` antes del primer APK serio** aunque todavía no se usen.

**Push en el APK:** hace falta un proyecto Firebase, `google-services.json` y la clave FCM V1 subida a EAS (https://docs.expo.dev/push-notifications/push-notifications-setup/). Es 2–4 h de trabajo administrativo del CTO, no de código.

## 7. Conexiones Postgres en Fluid compute — MEDIO

**Evidencia:** `apps/api/src/db.ts:7-9` crea `new PrismaPg({ connectionString, connectionTimeoutMillis: 5000 })`, así que Prisma crea su propio pool con `max` por defecto de 10, sin `attachDatabasePool` y sin listener de `error`.

- Vercel: "Call attachDatabasePool() right after creating a database pool… ensures that idle pool clients are properly released before functions suspend" (https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package).
- Prisma 7: "pass your own `pg` pool so you can attach the `error` listener and `attachDatabasePool` to it"; `max` reemplaza `connection_limit` (default 10) (prisma/web, `connection-terminated-unexpectedly.mdx`, vía context7).
- **Síntoma típico** si falta: "Connection terminated unexpectedly" esporádico tras una instancia suspendida. O, peor, un `error` de un cliente inactivo sin listener que tumba el proceso cuando Neon cierra conexiones al suspenderse.

**Arreglo**

```ts
const pool = new Pool({
  connectionString,
  max: 5,
  idleTimeoutMillis: 10_000,
  connectionTimeoutMillis: 5000,
});
pool.on('error', (e) => console.error('pg pool:', e.message));
attachDatabasePool(pool);
export const prisma = new PrismaClient({ adapter: new PrismaPg(pool) });
```

- Dependencias nuevas: `@vercel/functions` y `pg` directo; hoy `pg` es transitiva de adapter-pg.
- Seguir con la URL pooled (PgBouncer de Neon). No agregar `pgbouncer=true` (Prisma lo desaconseja con PgBouncer ≥1.21).

**Esfuerzo:** 30 min más tests.
**No verificado:** que el fallo ocurra hoy en producción (no hay acceso a los logs del proyecto). Riesgo latente, no observado.

## 20. Lo que sobra o es riesgo para 19 días, y qué simplificar

1. **Push (RF-24/25/27) es la pieza más cara y de menor valor marginal.** Necesita cuenta Expo, Firebase, credenciales FCM V1, un APK nuevo, registro del token, envío en el handler y deep link. Orden propuesto:
   - (a) el núcleo en el teléfono hoy, con Expo Go;
   - (b) el primer APK `preview` con `expo-notifications`, `expo-sqlite` y `expo-updates` ya incluidos, antes del ~20-nov;
   - (c) offline (RF-29..31), que es solo JS sobre TanStack persist y se puede iterar con `eas update`;
   - (d) push al final, solo si (a)–(c) están verdes.
2. **No hacer antes de la demo:** Upstash o store compartido para el rate limit, pino, Maestro, ramas Neon por preview, Sentry/EAS Observe, automatizar migraciones en CI.
3. **Neon Auth activado y no conectado** (`handoff.md:27`, `neon.ts:5` `auth: true`): superficie muerta que confunde (crea su propio schema y un servicio). Desactivarlo o dejar escrito que no se usa. **No verificado:** qué objetos creó en la BD.
4. **`neon.ts` + `@neon/config` + `@neon/env`** (`package.json:16-17`): tooling sin uso real y con la trampa del TTL de 7 días (#3). Candidatos a quitar.
5. **`react-native-web` / `react-dom`** solo sirven para las capturas en navegador. Se pueden mantener (ya funcionan), pero no invertir en Expo web ni en CORS.
6. **iOS:** fuera de alcance (Expo Go de la App Store se queda en SDK 54; TestFlight requiere Apple Developer). Confirmado como decisión del plan.
